## Phase 10 — Shorts & clips

Batch: `analyzeViralMoments`, `extractBestMoments`, `downloadYouTubeVideo`,
`enhanceClipForFYP`, `detectSilencesAndFillers`, `scheduleClipPost`. 8 manual items.

### 10a · `downloadYouTubeVideo` — Bunny → R2 *(the only real work here)*

It pulls a YouTube video via Cobalt and stores it, currently on Bunny, using
`Core.UploadFile` plus four `BUNNY_*` env vars. Replace the whole storage block:

```ts
import { ingestUrl } from '../lib/r2';

// Cobalt hands back a temporary URL; re-host it so the stored link does not rot.
const stored = await ingestUrl(ctx, cobaltUrl, { prefix: 'youtube' });
const stable_video_url = stored.url;
```

Keep the returned field names exactly — `directApi.resolveYouTubeVideo` reads
`stable_video_url`, `video_url`, `stable_audio_url`, `audio_url` and falls back between
them.

`COBALT_API_URL` stays an optional BYOK setting (it is a URL, not a secret, and points at
your own instance). The codemod already mapped it to `ctx.keys.get()` because the
original null-checked it — leave that as `get()`, and leave the existing "not configured"
branch reachable.

### 10b · `scheduleClipPost` calls another function

Import the handler and call it in-process — `await other(payload, ctx)` — never over
HTTP. Note this function only writes `UploadMetadata` rows with
`record_type: 'scheduled_post'`; it does not publish anything (YouTube publishing was
dropped). `record_type` is a real column precisely because this filters on it.

### 10c · Optional keys and `ctx` injection

`analyzeViralMoments` null-checks **both** `GEMINI_API_KEY` and `ANTHROPIC_API_KEY` and
falls back between them, so both became `ctx.keys.get()`. That is correct — the fallback
chain is the point. Same for `extractBestMoments` (Gemini) and `enhanceClipForFYP`
(Anthropic).

`analyzeViralMoments` also has a `callBase44LLM` helper. Point it at `invokeLLM` from
`lib/ai.ts`; keep the function name and its position in the fallback chain.

## Phase 11 — Topics, SEO & b-roll

Batch: `generateTopics`, `parseAndScheduleTopics`, `researchNicheStrategy`,
`generateSeoTitlesDescriptions`, `generateSeoDescriptions`, `searchBrollVideos`,
`autoBrollPopulate`, `sleepBrollPopulate`. Clean — zero manual items.

### 11a · Two functions are invoked by a **dynamic name**

`src/components/content/AutoBrollButton.jsx:25` does:

```js
const fnName = isSleep ? 'sleepBrollPopulate' : 'autoBrollPopulate';
const res = await base44.functions.invoke(fnName, { project_id: projectId });
```

A grep for `invoke('autoBrollPopulate')` finds nothing, which is why these two look dead
and nearly got dropped. **They are live.** Both must be registered under exactly those
names. `src/pages/ContentGeneration.jsx:499` has the same dynamic-name pattern.

### 11b · Preserve the chunked b-roll contract

`autoBrollPopulate` / `sleepBrollPopulate` return `{ populated, total, remaining, done }`
and `AutoBrollButton` loops until `done !== false`, accumulating `populated`. Keep every
one of those field names and the per-invocation batch size. This is the resumable pattern
that keeps these functions inside Workers' limits — do not collapse the loop server-side.

### 11c · `researchNicheStrategy` is the lone survivor of area B

Everything else in niche intelligence was dropped, but `CreateChannelDialog` calls this
one to fill a new channel's strategy. It writes `Channels.script_strategy` as a JSON
string. Port it, register it, and do not let its lonely presence tempt anyone into
reviving `fetchNicheTrends` or `discoverCompetitors`.

### 11d · SEO — the surviving half of area N

`generateSeoTitlesDescriptions` and `generateSeoDescriptions` feed PostProduction's
Titles and Descriptions tabs and write `UploadMetadata`. They generate copy; they upload
nothing. `TopicAssetsPanel` in ChannelDetail also reads that entity.

`parseAndScheduleTopics` is the one place `YOUTUBE_API_KEY` is still used — read-only
metadata while scheduling topics. It stays an optional key.
